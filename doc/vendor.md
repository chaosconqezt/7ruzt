# Движок: 7-Zip CLI и `vendor/`

## Политика поиска

7-Zip **не ищется в системе** — он поставляется вместе с программой и лежит
в одной папке с её исполняемым файлом: `target/<профиль>/` при сборке из
исходников или рядом с установленным `archiver-app`. Туда его кладёт
`core/build.rs` (ядро — общая зависимость `app` и `cli`, поэтому один скрипт
обслуживает обе сборки).

Имя бинарника зависит от платформы: `7z.exe` на Windows, `7zz` (или `7z`) на
unix. `PATH`, `SEVENZIP_PATH` и другие переменные окружения не опрашиваются:
иначе на машине разработчика легко подхватить чужой или старый 7-Zip.

**Минимальная версия — 21.07, ниже отказ.** В 21.07 появился `-sccUTF-8`
(UTF-8 вывод в консоль); без него имена файлов приходят в системной кодировке
и ломаются, поэтому старые версии не принимаются: `Locator::resolve` возвращает
ошибку «версия ниже минимальной 21.07». Версии 21.07–23.01 работают, но показывают
предупреждение «7-Zip 22.00 устарела: рекомендуется 26.06 или новее, возможны
глюки». Отказ также если 7-Zip не найден вообще или найденный бинарник не
запускается.

## Что лежит в vendor

Запиненный 7-Zip `26.06` (2026-11-06), x64, всё зафиксировано хешами в
`manifest.json`.

Windows — `vendor/7zip/win-x64/`:

| Файл | Зачем |
|---|---|
| `7z.exe` | консольный архиватор, вся работа идёт через него |
| `7z.dll` | кодеки остальных форматов (7z работает и без него, но zip/rar/iso — нет) |
| `License.txt` | лицензия 7-Zip (LGPL 2.1 + оговорка unRAR) |
| `VERSION` | версия одной строкой — для быстрой проверки без запуска бинаря |

Linux — `vendor/7zip/linux-x64/`: один статический бинарь `7zz` (все кодеки
внутри, DLL нет), `License.txt` и `VERSION`. Из архива `7zzs` (статическая
сборка) не берём.

macOS — две папки, потому что официальные сборки раздельные: `macos-arm64/`
(Apple Silicon, `7z2606-mac.tar.xz`) и `macos-x64/` (Intel,
`7z2606-mac-x64.tar.xz`). В обеих тот же `7zz`, `License.txt` и `VERSION`;
`build.rs` выбирает папку по `CARGO_CFG_TARGET_ARCH`.

Из полного дистрибутива **не** нужны: `7zFM.exe` / `7zG.exe` (чужие GUI),
`7-zip.dll` / `7-zip32.dll` (проводниковые расширения), `Uninstall.exe`, `Lang\`
(локализации 7-Zip не нужны — свои строки), `7z.sfx` / `7zCon.sfx` (добавим, если
понадобится создавать SFX), `7-zip.chm`.

**Исходники 7-Zip не вендорим.** Программа не линкует `7z.dll` и не собирает
7-Zip, а запускает `7z.exe` дочерним процессом; всё, что нужно знать о бинаре,
узнаётся через `7z.exe i`. Понадобится собирать под другую архитектуру или звать
DLL через FFI — тогда добавим (`https://github.com/ip7z/7zip/releases` →
`7z2606-src.7z`). Для лицензионной комплектности достаточно `License.txt` +
ссылки на исходники.

## Обновление

```powershell
.\scripts\update-7zip.ps1                       # переустановить запиненную версию, сверить хеши
.\scripts\update-7zip.ps1 -Version 26.08 -Force # обновиться и переписать манифест
.\scripts\update-7zip.ps1 -Platform linux-x64   # то же для линуксового 7zz
.\scripts\update-7zip.ps1 -Platform macos-arm64 # 7zz для Apple Silicon
.\scripts\update-7zip.ps1 -Platform macos-x64   # 7zz для Intel Mac
```

Скрипт качает архив с github.com/ip7z/7zip (`windows-x64` — NSIS-установщик,
`linux-x64`/`macos-*` — `tar.xz`), распаковывает его **не устанавливая в
систему**, копирует нужные файлы, для Windows снимает Mark of the Web, сверяет
SHA-256 и обновляет `manifest.json` + `VERSION`.

Платформы в манифесте: `windows-x64` (`7z.exe` + `7z.dll`), `linux-x64`,
`macos-arm64` и `macos-x64` (по одному `7zz`). На unix официальный 7-Zip —
один статический бинарь, без DLL.

## ADR 0001. Обёртка над `7z.exe`, а не 7z-кодек на Rust

**Статус:** принято · **Дата:** 2026-11-09

### Контекст

Нужен кроссплатформенный GUI-архиватор на Rust + GPUI, повторяющий 7-Zip File
Manager. Объём v1: только `.7z`, распаковка и создание, многотомные архивы, все
ядра, пароли. Задел на другие форматы.

Два кандидата в движок:

- **A.** запускать официальный `7z.exe`/`7zz` дочерним процессом и разбирать вывод;
- **B.** pure-Rust `sevenz-rust2` (0.25.x, Apache-2.0, features `aes256`, `ppmd`,
  `bzip2`, `zstd`, `brotli`, `lz4`, `deflate`).

### Решение

**Вариант A.** `7z.exe` из `vendor/7zip/` поставляется рядом с программой и
запускается дочерним процессом. Собственного кодека не пишем.

### Почему

| Критерий | A. CLI | B. `sevenz-rust2` |
|---|---|---|
| Полнота формата | эталон (сам 7-Zip) | ~90 %, редкие архивы ломаются |
| Кодеки и фильтры | все, включая BCJ2 | основные, BCJ2 нет |
| Многотомники / SFX / восстановление | да | нет |
| Тонкие настройки сжатия | полный паритет (`-m0`, `-md`, `-ms`, `-mmt`) | ограничено |
| Скорость | эталон, многопоточно | в разы медленнее на мелочи |
| Прогресс и отмена | парсинг `-bsp1`, kill процесса | точнее нативно |
| Своих строк кода | ~2–3 тыс. | ~7.5 тыс. чужого, но в дереве |

Ценность продукта — UI и UX, а не кодеки. CI на Linux/macOS без GUI всё равно
проверяет именно ядро, и это дешевле делать поверх стабильного CLI.

### Последствия

- **Резолв бинарника** — только поставка: бинарник лежит рядом с исполняемым
  файлом программы; `PATH` и переменные окружения не опрашиваются.
- **Устаревшая версия — предупреждение, не отказ** (см. политику выше).
- **`-sccUTF-8`** требует 21.07+; ниже — отказ на этапе `Locator::resolve`.
- **Лицензия**: 7-Zip — LGPL 2.1 (+ оговорка unRAR). `7z.dll` не линкуем, поэтому
  достаточно поставлять бинарь отдельно, `License.txt` и ссылку на исходники.
  RAR — только распаковка.
- **Исходники 7-Zip не вендорим**, пока не линкуем DLL.
- **Границы**: разбор вывода 7-Zip не в UI-потоке; `-slt` парсится в отдельном
  потоке, в UI уходят только события (прогресс/ошибка/готово).
