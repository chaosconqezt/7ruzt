# Архитектура

Приложение — один бинарник `archiver-app`. Кода два слоя: **состояние и логика**
(`window.rs` + модули без префикса) и **отрисовка** (`ui*.rs`). Логика не знает
про элементы, отрисовка не меняет состояние — только зовёт методы окна.

## Модули (все плоско, `app/src/`)

| Файл | Что внутри |
|---|---|
| `main.rs` | точка входа: `mod`-декларации, общие импорты, `fn main` |
| `launch.rs` | разбор аргументов (тестируемо, без окна) |
| `window.rs` | `MainWindow` (поля), `ViewMode`, `ToolAction`, `Modal`, запуск окна |
| `panel.rs` | `Panel`: путь, содержимое, выделение, вид, прокрутка одной панели |
| `keys.rs` | `handle_key`: модалки → прогресс → правка в строке → список |
| `select.rs` | выделение: клик/Ctrl/Shift, курсор, рамка (`RubberBand`) |
| `nav.rs` | вход/выход, перезагрузка, сортировка, адрес, заголовок окна, дроп |
| `menu.rs` | модель меню (пункты, маркеры, горячие клавиши), `run_action` |
| `job.rs` | фоновая операция: `Job`, прогресс, отмена, «Фон», итоги |
| `archive.rs` | создание / извлечение / проверка: диалоги и запуск 7z |
| `files.rs` | папка/файл (F7, Ctrl+N), переименование в строке (F2), удаление |
| `transfer.rs` | копирование/перемещение: путь назначения, политика совпадений |
| `picker.rs` | дерево выбора папки (ленивое) |
| `dialogs.rs` | данные диалогов (`CreateDialog`, `ExtractDialog`, …) |
| `shell.rs` | открыть системой, свойства, PowerShell без `unsafe` |
| `fsutil.rs` | мелкие файловые помощники: ошибки, объём, листинг |
| `icons.rs` | системные значки: оболочка Windows/macOS и тема freedesktop на Linux, кеш по расширению, фоновая загрузка, пробники для архива |
| `prelude.rs` | внутренний prelude: `use crate::prelude::*` в каждом модуле |
| `theme.rs` | тема (системная/светлая/тёмная/свои палитры), загрузка `app/themes.json`, масштаб шрифта, единый размер контролов, метрики |
| `text.rs` | человеческий размер, время, склонение |
| `diag.rs` | лог `ui.log`, счётчики кадра/ввода |
| `ui.rs` | `impl Render`: каркас окна и порядок слоёв |
| `ui_chrome.rs` | меню-бар, тулбар, адресная строка, статус-бар |
| `ui_list.rs` | список: таблица/список/значки, строки, рамка, скроллбар, drag |
| `ui_menu.rs` | попапы меню |
| `ui_widgets.rs` | общие мелочи диалогов (кнопки, каркас, «✕»/«Y») |
| `ui_dialog_create.rs` | «Добавить к архиву» |
| `ui_dialog_simple.rs` | извлечение, проверка, папка/файл, перенос |
| `ui_dialog_picker.rs` | дерево папок |
| `ui_dialog_progress.rs` | окно прогресса |
| `ui_about.rs` | «О программе» |

Палитры «Тёмная» (Carbon), «Блэкаут», «Графит», «Серебро», Barbie, My Little
Pony, «Гжель» и «Гуро» — не код, а `app/themes.json` в формате темы
gpui-component; `theme.rs` только ищет тему по имени и применяет её.

Добавили файл — добавьте `mod` в `main.rs` и, если это тип/функция для других
модулей, `pub(crate)` + строку в `prelude.rs`.

## Панели

В окне две равноправные панели (`panels: [Panel; 2]`). Видна сначала одна;
F9 включает вторую, Tab переключает активную. Всё «где мы и что видим» (путь,
архив, записи, выделение, сортировка, вид, прокрутка, рамка) живёт в `Panel`;
меню, тулбар, диалоги, фоновая операция и статус-бар — общие и работают с
активной панелью (`active()`, `active_mut()`). Вторая панель создаётся лениво:
не хочется на старте второй раз запускать 7z ради скрытого списка.

Рендер: `ui_chrome::panels_view` строит одну панель или две рядом, у каждой свой
адрес, шапка (только в режиме таблицы) и список; рамки протяжки рисуются в корне
окна отдельно для каждой панели.

## Состояние и модалки

`MainWindow` — одна сущность GPUI. Модальные диалоги взаимоисключающие, поэтому
лежат в одном поле:

```rust
enum Modal { Create(..), Extract(..), Test(..), Prompt(..), Transfer(..), About }
```

`modal_open()` / `close_modal()` / `confirm_modal()` — единственные места, где
перечислены все диалоги. Новый диалог добавляется в `Modal`, `modal_overlay`
(в `ui.rs`) и `confirm_modal`; забыть его в одной из копий уже нельзя.

Подтверждение удаления в этот перечень не входит: это диалог кита
(`open_alert_dialog`), он живёт в слое `WindowState` и при открытии сам владеет
клавишами (`window.has_active_dialog`).

Отдельно живут:

- `folder_picker` — дерево папок **поверх** диалога извлечения/переноса;
- `rename` — правка прямо в строке (не окно);
- `job` — фоновая операция: окно прогресса, но не модалка (список скрыт,
  статус-бар виден).

## Фоновые операции

7z и файловые операции идут в отдельном потоке, UI только опрашивает канал:

```text
UI поток                     фоновый поток
start_job(...)  ──spawn──▶   create/extract/test/copy → send(Progress|Totals|Done)
опрос раз в 100 мс  ◀──────  mpsc::Receiver
```

Отмена — `Arc<AtomicBool>`: 7z убивается, копирование проверяет флаг между
файлами. Окно прогресса показывает процент, текущий файл, оценку остатка и
скорости; для упаковки ещё размер архива и степень сжатия (в CLI 7z других цифр
нет). Код возврата 1 — «сделано, но не всё» (предупреждение, не успех).

7-Zip обновляет прогресс серией `\b` (ClearPrev), а не `\r`, поэтому
`read_progress` режет токены по `\r`, `\n` и `\x08`. Из строки прогресса
`parse_progress` берёт процент; имена файлов идут отдельными строками: при
упаковке с `+`, при извлечении с `-`, при проверке с `T`, при обновлении с `U`.

## Список и производительность

- Таблица/список/значки — `uniform_list`: строки строятся только для видимого
  диапазона. Сетка виртуализирована по **рядам** клеток.
- Фиксированные высоты (`theme::ROW_H`, `tile_height`) — требование
  виртуализации.
- Строки и подписи строятся строго лениво только для видимого диапазона
  (`range`) внутри `uniform_list`: `Panel.entries` оборачивается в `Arc`,
  что исключает аллокации строк и форматирование для десятков тысяч файлов.
- Рамка выделения в сетке значков считается как 2D-прямоугольник (строки и
  столбцы), а не одномерный срез.
- Рамка выделения считается по геометрии списка, а не по строкам; якорь хранится
  в координатах содержимого.
- Клик после протяжки отбрасывается по сдвигу > 4 px (`DRAG_THRESHOLD`).

## Флаги диагностики

| Переменная | Что делает |
|---|---|
| `ARCHIVER_UI_LOG=1` | буферизованный лог `ui.log`: нажатия, клики, кадры |
| `ARCHIVER_FPS=1` | непрерывный замер: `60 fps · 16.7 мс · кадр 0.3 мс` |
| `ARCHIVER_TEST_FLAGS=1` | тестовые флаги: `--dump-state`, `--press`, `--quit-after` |

Обычный режим рисует кадр только по изменению состояния, поэтому «fps» имеет
смысл лишь в непрерывном замере. В статус-баре всегда видно `кадр N мс` и
`ввод N мс` — это наша работа, а не ожидание платформы.

## Drag & Drop между панелями

- При перетаскивании целевая папка или целевой архив ярко подсвечиваются (`drag_over` с повышенной контрастностью), чтобы исключить промахи.
- Отпускание на папку: копирование (без Shift) или перемещение (с Shift).
- Отпускание на архив или внутрь открытой панели архива: добавление файлов в архив через `7z a`. При зажатом Shift — перемещение в архив (исходные файлы удаляются после добавления).
- Записи, выделенные внутри архива, тоже можно тянуть: сброс на папку распаковывает только их (`7z x` с явными именами), наружу из окна они не отдаются — на диске их ещё нет.
- Перетаскивание из проводника/Finder/Nautilus — это тоже копирование в текущую папку панели (или в папку под курсором), Shift — перемещение. Одиночную папку не «открываем», а копируем.
- Защита от рекурсивной упаковки: добавление архива в самого себя блокируется.
- Чистая логика вынесена в `transfer::resolve_drop` и покрыта unit-тестами.

## Тесты

`core/` — вся независимая логика. В приложении (`app/`) — разбор аргументов,
2D-выделение в сетке, выделенные пути архива, логика Drag & Drop и кодирование
shell. Актуальное число тестов — в выводе `cargo test --workspace`.

Гейты:

```powershell
cargo fmt --all --check
cargo clippy --workspace --offline --all-targets -- -D warnings
cargo test --workspace --offline
```
