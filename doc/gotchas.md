# Грабли, уже пойманные

Здесь то, что однажды сломало поведение и было починено. Читать перед правкой
соответствующего места: половина пунктов — неочевидные следствия платформы.

## 7-Zip и листинг

- 7-Zip на Windows отдаёт пути в `-slt` через `\` — нормализуем к `/`.
- Даты приходят с долями секунды (`17:20:09.4759984`) — обрезаем до минут.
- `-sccUTF-8` есть только с 21.07; ниже — **отказ** на этапе `Locator::resolve`
  (системная кодировка ломала имена, запасного пути больше нет).
- 7z первым делом печатает эхо пути (`ERROR: <путь> : <путь>`), причина идёт
  следующей строкой. В статус-бар берём последнюю строку (`open_failure`).
- Часть ошибок 7z печатает только в **stdout** (`Open ERROR: Cannot open the file
  as [7z] archive`, `ERRORS: Is not archive`), stderr при этом пуст. Строки
  собираем из обоих потоков (`run::diagnostic_line`), но эхо `ERROR: <путь>`
  отбрасываем.
- Код возврата 7z `1` — «сделано, но не всё»: предупреждение, не успех.
- У `7z t` на шифрованном архиве без `-p` пароль берётся со stdin, а у нас там
  `nul`: 7z доходит до «Enter password», получает конец файла и выходит с кодом
  255 («Break signaled»). Шифрование определяем по `Encrypted = +` в `-slt` и
  спрашиваем пароль **до** запуска.
- **Пароль передаётся в аргументе (`-p…`) и виден в командной строке процесса**
  любому локальному пользователю. Риск принят осознанно: piped stdin 7z 26.06
  не читает (проверено: `echo pw | 7z t -p` даёт код 2 «Can't open as archive»),
  другого безопасного канала у CLI-движка нет. Архивы с зашифрованными именами
  (`-mhe=on`) без пароля не листятся, поэтому их шифрование probe не видит —
  это задокументированное ограничение, а не баг.
- `-md` (словарь) понимают только LZMA и LZMA2; для PPMd/BZip2/Deflate/Copy
  аргумент не передаём — у них это другой параметр или ошибка 7z.
- Без `--` перед путями 7z принимает архив с именем на дефис за переключатель и
  падает с «Command Line Error» (код 7).

## Список, выделение, мышь

- `uniform_list` требует `'static`-замыкание: данные строк собираем в `Vec`,
  клики — через `WeakEntity::update`, а не через `&self`.
- Клавиатуру слушаем на **корне окна**, а не на списке: под модалкой список не
  рисуется, и вместе с ним пропал бы весь ввод.
- Рамка выделения считается по геометрии списка, а не по строкам: верх списка и
  прокрутку отдаёт `UniformListScrollHandle` (`base_handle.bounds()` — окно,
  `offset().y` — отрицательный при прокрутке вниз). Начало рамки храним в
  координатах содержимого (`content_y`), иначе при автопрокрутке якорь уезжает
  вместе со строками.
- Клик после протяжки: строка получает `on_click`, даже если мышь уехала в её
  пределах. Поэтому `ClickEvent::Mouse` проверяем на сдвиг больше 4 px
  (`DRAG_THRESHOLD`) и такой «клик» не применяем — выделение уже построено
  рамкой.
- Рамка и перетаскивание объекта не должны спорить: `on_drag` висит только на
  значке и имени, а их `on_mouse_down` останавливает всплытие. Протяжка с любого
  другого места строки (пустой хвост колонки имени, размер, даты) строит рамку,
  а не тащит файл — как в 7-Zip FM.
- Клик без протяжки снимает выделение только если рамка началась ниже строк
  (`RubberBand::started_on_empty`): иначе клик по колонке размера спорил бы с
  выделением строки.
- Нажатие на значок/имя останавливает всплытие (иначе список начинал бы рамку),
  а `on_click` строки регистрирует нажатие на всплытии — значит, клик по имени
  не выделял строку, только пустой хвост справа. Теперь выделение объекта идёт
  **на mouse down** в его обработчике (`row_clicked`), а уже выделенную строку
  без модификаторов не схлопываем, чтобы не потерять Ctrl-набор при перетаскивании.
- Сетка значков виртуализирована **по строкам** — одна строка `uniform_list` это
  ряд клеток; число колонок берём из ширины самого списка (прошлый кадр), а не из
  окна, иначе колонки разъезжаются с полосой прокрутки.
- `ElementId` не понимает тройной кортеж `("row", panel, index)`: в двухпанельном
  режиме id строки — `index * 2 + panel`, id шапки — `key * 2 + panel`. Иначе
  сборка падает на `From<(&str, usize, usize)>`, а одинаковые id в двух списках
  ещё и путали бы состояние наведения.
- Рамка, выделение и прокрутка живут в `Panel`, а не в окне: при протяжке во
  второй панели нельзя считать геометрию по первой. `rubber_rect` рисуется в корне
  окна, но координаты берёт из `list_scroll` своей панели.
- Рамка в сетке считает объект по `x` и `y` (`entry_at`), в таблице — только по
  `y`. Автопрокрутка шагает на высоту клетки, а не строки.
- Скроллбар списка — `Scrollbar` из кита: `UniformListScrollHandle` реализует
  `ScrollbarHandle`, поэтому ползунок тянется мышью. Своя полоса была
  нарисованной и не реагировала на мышь.

## Меню

- `Button::dropdown_menu` из кита держит открытое состояние внутри `Popover` и
  не даёт программно переключить попап. Поэтому верхнее меню собрано на
  `PopupMenu` + `anchored`/`deferred`: `open_menu` хранится у окна, а наведение
  на соседний заголовок пересоздаёт попап под ним. При смене пункта старую
  подписку на `DismissEvent` снимаем до создания новой, иначе старое закрытие
  закрыло бы только что открытое меню.
- Фокус после закрытия возвращаем списку, только если он остался в попапе.
  Иначе выбор пункта, открывающего диалог, отбирал бы фокус у поля ввода.

## Клавиши и фокус

- **Tab в gpui-base занят**: `Root` вешает `tab → focus_next`, поэтому наш
  `on_key_down` её не получает и `capture_key_down` тоже — биндинги диспатчатся
  раньше событий элемента. Своё действие `SwitchPanel` привязано к контексту
  `"Archiver"` (он на корне окна), а в диалогах обработчик сам зовёт
  `focus_next`, чтобы Tab продолжал ходить по полям.
- Enter на файле архива — штатный вход, как в 7-Zip FM, по
  `format::is_archive_name`: заголовок не читаем, иначе каждый Enter на обычном
  файле стоил бы запуска 7z. Вход только после удачного листинга — битый файл
  оставляет в каталоге с причиной в статус-баре.
- Вложенный архив (архив внутри архива) не открываем: 7z этого не умеет без
  распаковки. Вместо тишины — подсказка в статус-баре.
- Выход из архива (Backspace из корня) выделяет сам архив в каталоге — иначе
  Enter → Backspace → Enter снова начинается с поиска строки.
- Пока открыто дерево папок, фокус забираем у поля «Куда»: иначе печать уходила
  бы в невидимое поле под модалкой. Крестик у дерева свой.
- Переименование (F2) — прямо в строке. Клик по строке **тоже** приходит, когда
  он попал в поле ввода, и её `on_click` уводил фокус в список — правка тут же
  завершалась. Поэтому строка, которая правится, свои клики игнорирует.
- Если сохранение случилось по потере фокуса от того же клика, список уже
  перечитан — такой клик отбрасываем (`rename_finished`), иначе он выделит
  строку по старому индексу.
- F2 работает в том виде, в котором человек сейчас находится: в таблице поле
  встаёт вместо имени, в клетке сетки — вместо подписи. У мелких значков при
  правке иконку убираем: поле ввода выше клетки (44 px).
- Alt+Enter (свойства) — `ShellExecuteEx` с `SEE_MASK_INVOKEIDLIST` через
  `Add-Type` в PowerShell: глагол `properties` через `Shell.Application` на части
  сборок Windows молчит. Скрипт уходит через `-EncodedCommand` (UTF-16LE +
  Base64): у `-Command` кавычки и here-string ломаются.
- F3 и F4 часто открывают одно и то же приложение — это не баг. F3 просит `open`,
  F4 — `edit`; у большинства типов `edit` не зарегистрирован, и Windows открывает
  программу по умолчанию (fallback на `open` сделан явно, чтобы F4 не молчала).
- Запускаемое приложение держит свой exe: `cargo build` падает с «Access is
  denied». Закрой окно (или `Stop-Process -Name archiver-app`).

## Перетаскивание и приём файлов

- Внутреннее перетаскивание между панелями — отдельный тип payload
  (`DragFiles`), а не `ExternalPaths`: у списка висят два `on_drop`, и тип
  выбирается по типу перетаскиваемого значения. Для внутреннего drag
  `on_drag` уже создаёт `DragFiles`; drop копирует в каталог принявшей панели
  (`start_transfer`, Shift — move), поэтому прогресс и отмена те же, что у F5/F6.
- Цель drop считаем по `window.mouse_position()` (это координаты **клиентской**
  области, без заголовка окна) и строке под курсором: папка — внутрь неё,
  иначе — текущий каталог панели. Без этого «перетащил в панель» означало бы
  только текущий каталог, и попасть в папку было нельзя.
- Дроп из проводника/Finder/Nautilus — это копирование в папку панели
  (Shift — перемещение), а не открытие пути: одиночную папку тоже копируем,
  иначе перетаскивание из файлового менеджера просто меняло адрес панели.
- Записи архива перетаскиваются отдельным payload (`DragArchive`): путей на
  диске у них нет, поэтому внешних `external_drag_payload` у него нет, а
  `on_drop` распаковывает ровно перечисленные записи.
- Дроп из проводника приходит от OLE (`RegisterDragDrop`), а не от нашей мыши:
  `Entered` создаёт активный drag, `Pending` — движение, `Submit` превращается в
  mouse-up. Без `Entered` `on_drop` не сработает, а подсветка `drag_over` живёт
  только пока идёт `Pending`. Поэтому дроп вешаем на сам список.
- **Обратный drag (файл из окна в проводник) на Windows не работает** — не наша
  недоделка: `start_external_drag` в `gpui-pre-windows` не реализован (в
  платформе `can_start_external_drag() == false`). Работает на macOS и Wayland,
  поэтому вызов `external_drag_payload` оставлен. Чтобы поднять drag-out на
  Windows, нужен форк с OLE `DoDragDrop` — решение владельца проекта.

## Файловые операции

- Имя проверяется до обращения к диску (`check_name`): `.`/`..`, символы
  `< > : " / \ | ? *`, управляющие, хвостовая точка, зарезервированные имена
  Windows (`CON`, `COM7`… — даже с расширением). Хвостовой **пробел** срезаем.
- Переименование только со сменой регистра (`photo.jpg` → `Photo.jpg`) — не
  коллизия: `rename_in` сравнивает имена без регистра.
- Удаление **безвозвратно**, корзина не используется — диалог говорит об этом
  прямо. Ссылку удаляем саму (`symlink_metadata`), не заходя в цель.
- Внутри архива создание, переименование и удаление запрещены: вместо тишины —
  «сначала извлеките».
- Копирование/перемещение идут фоном и шлют те же `Progress`, что 7z, поэтому
  окно операции общее. Перемещение удаляет источник **только после** успешной
  записи; при отмене недописанный файл удаляется, исходник остаётся.
- Перемещение «в этот же каталог» — не ошибка: канонические пути совпали →
  объект пропускается. Иначе политика «Заменить» удалила бы файл до копирования.
- Папку внутрь себя копировать нельзя: `resolve_destination` сравнивает
  канонические пути (`InvalidInput`).
- Политика совпадений — та же `Overwrite`: «Заменить» = Replace, «Пропустить» =
  Skip, «Переименовать» = Rename (`a (2).txt`).
- Путь назначения как `cp`: существующий каталог — внутрь; слэш на конце или
  несколько объектов — `create_dir_all` и внутрь; **один** объект в
  несуществующий путь — как новый файл/папку с этим именем.
- Дерево выбора папки ленивое: дети читаются только у развёрнутых узлов. `A:`/`B:`
  не показываем: на машине с флоппи-приводом обращение подвешивает открытие.
- Имя архива по умолчанию — от **одного** выделенного объекта (папка целиком,
  файл без расширения), иначе от текущего каталога.

## Диалоги и прогресс

- Повтор пароля сравнивается до запуска 7z: опечатка даёт недоступный архив.
  Число потоков — только целое > 0.
- Пароль маскируется (`InputState::masked`), «Показать пароль» переключает маску
  у **обоих** полей через `set_masked`.
- Ошибки «имя занято»/«имя пустое» — **внутри** диалога красной строкой: внизу
  окна их не видно.
- Окно прогресса: 7z в CLI даёт только процент и имя файла (`-bb1`), поэтому
  «Осталось» и скорость — оценки из времени и объёма. «Сжатый» и степень сжатия —
  для упаковки (размер файла архива на диске).
- 7-Zip обновляет консольный прогресс **не через `\r`**, а через `\b`:
  `ClearPrev` пишет серию backspace, пробелы и снова backspace, затем текст
  ` 16% 4 + file`. Если считать границей только `\r`/`\n`, весь прогресс
  копится до EOF и шкала стоит на нуле. Поэтому `read_progress` режет токены
  ещё и по `\x08`, а `parse_progress` достаёт процент из токена прогресса.
  Имя файла берём **только** из отдельной строки `+ файл` (её печатает `-bb1`),
  иначе одна и та же запись придёт дважды и счётчик файлов удвоится.
- `-bb1` при упаковке пишет `+ файл`, при извлечении `- файл`, при проверке
  `T файл`, при обновлении `U файл` — все префиксы разбирает `item_name`.
- 7-Zip сам делает `fflush()` после каждого шага прогресса; блочная
  буферизация libc на Linux здесь ни при чём. Прогресс идёт в stdout (`-bsp1`)
  на всех платформах.
- Объём работы считаем до запуска 7z: для упаковки — обход источников **в фоне**;
  для распаковки/проверки — по листингу. Для ещё не открытого архива объём
  неизвестен — в окне «—», не выдумка.
- «Пауза» — «Y»: приостановить дочерний процесс без `unsafe` нельзя. «Фон»
  убирает окно, работа идёт, прогресс остаётся в статус-баре; Escape делает то же.
- Недоступное действие **гаснет**, а не молчит: «Извлечь»/«Тестировать» без
  архива, «Добавить» внутри архива, всё лишнее во время операции.
- «Извлечь»/«Проверить» на выделенном файле — штатный сценарий; «похож ли файл на
  архив» решает `format::is_archive_name`. Несколько выделенных архивов сразу не
  поддерживаем.
- Архив с зашифрованными **именами** в каталоге не отличить от битого до ввода
  пароля: «Проверить» покажет ошибку 7z, а не диалог пароля.
- Список под модалкой не строим: иначе каждое нажатие клавиши перерисовывает
  тысячи строк (это и было «фризит при вводе имени»).

- `TreeEvent::Expanded` приходит из `TreeState::toggle_expand`, где состояние
  дерева уже занято: пересобирать его прямо в обработчике нельзя (двойной
  borrow). Только через `cx.defer`, как в `picker_set_expanded`.

## Тема и текст

- `window.set_rem_size(px(…))` **не работает** для кегля: `Root` на каждой
  отрисовке ставит `rem = theme.font_size`. Кегль и гарнитура — только через
  `Theme::update` (см. `theme::init`).
- Дробный `rem` даёт дробные отступы кита. Для базового «Среднего» (12 px,
  rem 13,714) это принято осознанно: текст GPUI рисует с субпиксельным
  позиционированием, а свои высоты округляем (`theme::snap`). Если понадобится
  целый `rem`, выбери `font_px` кратный 0.875 (например, 14 px → rem 16).
- `DENSITY = 0.85` — межстрочный отступ на 15% меньше. Он применяется к
  `theme::row_h()`, плиткам и `menu_pad_y()`; не обходи его стороной в новых
  списках, иначе строки снова разъедутся. Внутренние отступы пунктов
  выпадающего меню принадлежат `PopupMenuItem` кита (min-height + `py_1`), их
  из приложения не переопределить.
- `Theme::apply_config` не только красит окно, но и регистрирует палитру как
  светлую/тёмную в теме кита. Поэтому перед «Светлой» и «Системной» мы
  возвращаем в реестр штатную светлую, а тёмную — Carbon: иначе «Системная»
  показала бы последнюю выбранную свою тему, а не «Тёмную».
- «Системная» ночью — это Carbon, «Блэкаут» — отдельная почти чёрная палитра
  (`#000000`). Не путай их: `ThemePreference::Carbon` и `Dark` теперь разные.
- `Theme::change` загружает конфиг режима и вправе переписать шрифт. Поэтому
  `theme::apply` ставит `rem()` **после** смены светлой/тёмной темы, иначе
  переключение молча вернуло бы системный кегль. Гарнитуру не трогаем: кит сам
  держит `.SystemUIFont` и подставляет установленную замену.
- Кегль меняется на лету, поэтому метрики — функции (`theme::row_h()`,
  `header_h()`, `status_h()`, `scrollbar_w()`), а не константы. Не заводи
  `const ROW_H`: при смене «Вид → Шрифт» список останется старой высоты, и
  стрелки начнут попадать в соседнюю строку.
- `System`-тема держится на `cx.observe_window_appearance`; подписку нельзя
  выронить (поле `theme_subscription` в `MainWindow`), иначе окно перестанет
  замечать переключение оформления ОС до перезапуска.
- Размеры элементов управления берём из `theme::CONTROL_SIZE`. Свой `.small()`
  или `text_size` на месте ломает единый ряд: соседние поля в диалоге
  становятся разной высоты.
- Цвета своих тем — только в `app/themes.json`, не в Rust. `theme.rs` читает
  файл рядом с exe (правится без пересборки), затем из текущего каталога, и
  только потом берёт встроенную копию. Ключи — как в теме gpui-component
  (`background`, `button.background`, `list.head.background`), а не наши имена.
- Хвост автодополнения адреса рисуется поверх `Input`: невидимая копия
  набранного текста занимает его ширину, палево-серый хвост идёт следом. Не
  привязывай его к `scroll_offset` — при длинном пути поле прокручено, и хвост
  должен просто исчезать, а не вставать в начало строки.
- Кнопки диалогов все идут через `ui_button()`: один вариант и один размер.
  Панель меню и тулбар остаются `ghost` — это осознанное исключение, чтобы не
  превращать шапку 7-Zip FM в ряд рамок.
- `.ps1` в Windows PowerShell 5.1 должен быть **UTF-8 с BOM**, иначе тире
  превращается в байт `0x94` (`”`), который PS считает кавычкой. Скрипты без
  кириллицы можно писать без BOM; с кириллицей — только с BOM.
