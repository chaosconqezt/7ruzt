# Интерфейс

## Откуда вид

Оформление перенесено из одноразового макета на том же gpui-kit (в репозитории
его нет — исходник теперь `app/src/theme.rs` + `ui*.rs`, вид зафиксирован в
`preview*.png`): меню, тулбар с буквенными значками операций, шапка таблицы,
диалоги, «О программе». Цвета — токены темы кита (`foreground`, `border`,
`list.*`), а не свои константы.

## Сначала кит, потом своё

Всё, что есть в `gpui-kit`, берём из него. Своё — только если в ките нет, и в
комментарии объясняем, почему.

| Задача | Брать из кита | Не делать |
|---|---|---|
| Текстовое поле | `component::input::{InputState, Input}` | свой `String` + `on_key_down` + каретка |
| События поля | `InputEvent::{Change, PressEnter, Blur}` через `cx.subscribe` | перехват клавиш на корне окна |
| Длинный список | `uniform_list` / `component::v_virtual_list` | все строки в `flex_col` |
| Кнопки, меню | `component::{Button, PopupMenu, DropdownMenu}` | div с `on_click` и самодельная рамка |
| Чекбоксы | `component::checkbox::Checkbox` | квадрат 12×12 с буквой `x` |
| Тема, размеры | `component::Theme`, `Sizable`/`Size` | магические числа на каждый виджет |

Проверено на своей шкуре: самописное поле ввода на `on_key_down` (руками
дописывали символы в `String`) давало **1060 мс задержки на нажатие** при кадре
0.4 мс. После перевода на `InputState` ввод стал мгновенным.

Эталон: `c:\vibecode\gpuidgc` — приложение на том же `gpui-kit` (`=0.9.0`, у нас
`=0.9.1`; при расхождении верь нашему `Cargo.lock`). Смотреть `app/ui/bars.rs`
(поля: `Input::new(&state).w_full()`), `dumper.rs` / `results.rs`
(`uniform_list`), `topbar.rs` (компоновка баров), `examples/gpui_probe.rs` (свалка
проверок API).

## Три состояния пункта

Неготовое не прячем: пункт стоит с **«✕»** в колонке маркера и погашен. Готовый
режим — «✓» и горячая клавиша справа. **«Y»** — не сделаем на этой платформе
(нужен COM, `unsafe` или файл, которого мы не поставляем: память упаковки, SFX,
пауза процесса). «Y» без причины — то же враньё, что живая кнопка, поэтому
причину пишем коротко в подписи, когда она не очевидна. Подменю (CRC, «Панели
инструментов», «Избранное») пока неготовые целиком — «✕» стоит в подписи самого
подменю.

Та же логика в диалогах: поле, которого нет, стоит погашенным с «✕»/«Y».

## Что уже взято из кита

- `StatusBar` — низ окна (слева «выделено», по центру статус, справа замер кадра);
- `Toolbar` — ряд кнопок операций;
- `Progress` — полоса в окне операции (`ProgressBar`, чтобы не путать с
  `core::Progress`);
- `Scrollbar` — полоса прокрутки списка; `UniformListScrollHandle` реализует
  `ScrollbarHandle`, поэтому ползунок тянется мышью;
- `Radio`/`RadioGroup` — уровень, метод и политика совпадений;
- `NumberInput` — число потоков;
- `GroupBox` — блок «Пока не реализовано»;
- `Tree`/`TreeState` — выбор папки: лениво, через погашенную заглушку «…» и
  событие `Expanded`; пересборка — через `cx.defer` (см. `doc/gotchas.md`);
- `AlertDialog` — подтверждение удаления.

## Кегль и гарнитура

Один кегль на всё окно, гарнитура — системная: на Windows это `Segoe UI Variable Text`
(родной шрифт Windows 11) с fallback на `Segoe UI`, на macOS — SF Pro, на Linux — системное
оформление. Кегль выбирается в «Вид → Шрифт»: **Малый / Средний / Большой**
(`theme::FontScale`). Базовый и выбранный по умолчанию — **Средний, 12 px** (9 pt):
малый на 1 pt меньше, большой на 1 pt больше. Кит задаёт кегль интерфейса как
`text_sm` = 0.875 rem, поэтому `theme::rem()` — это кегль, делённый на 0.875 (12 px → 13,714).
От `theme::font_size()` считаются все метрики окна, а от `theme::rem()` — отступы кита.

Масштаб и размеры элементов соответствуют Windows 11 Explorer:
- Строка списка в режиме таблицы: ровно **21 px** (`snap(rem() * 1.53125)`), что соответствует компактному виду Explorer (16 px значок + отступы);
- Значки элементов: стандартные размеры Windows **16×16 px** в таблице и обычном списке (`ICON_DETAILS` / `ICON_SMALL`) и **32×32 px** в крупных значках (`ICON_LARGE`);
- Шапка таблицы: **28 px** (`snap(rem() * 2.0)`);
- Статус-бар: **24 px** (`snap(rem() * 1.75)`).

## Значки

В списке — **системные значки ОС**, как в Проводнике: файл получает иконку
ассоциации, папка — стандартную папку, программа — свою. Всё живёт в `icons.rs`.

- **Windows/macOS**: `file_icon_provider` забирает значок у оболочки и прячет
  `unsafe` Win32/COM, наш линт `unsafe_code = "forbid"` не ослаблен.
- **Linux**: тема freedesktop читается напрямую через `freedesktop-icons`, без
  GTK и системных dev-пакетов. Текущая тема — `[Icons] Theme` из `kdeglobals`
  (KDE) или `gtk-icon-theme-name` из `settings.ini` (GNOME), иначе `gsettings`
  и `hicolor`. Имя значка — MIME типа (`application/pdf` → `application-pdf`)
  с откатом на общий `text-x-generic`/`image-x-generic`. PNG/SVG из темы
  отдаётся gpui как image-asset: он сам загружает и кеширует файл.

Кеш общий на обе панели: папки и файлы одного расширения запрашиваются один раз
(поэтому список из сотен `.txt` не дёргает систему на каждую строку), а
`.exe`/`.lnk` — по полному пути. Загрузка идёт **в фоне** после чтения панели:
оболочка отвечает синхронно, из кадра её звать нельзя. Пока значок не пришёл
или система его не дала, рисуется прежний встроенный SVG того же размера.

Записям внутри архива на диске ничего не соответствует. На Windows/macOS для
них используется пустой файл-пробник с тем же расширением в `%TEMP%\7zO-icons`
(оболочке нужен существующий путь); на Linux хватает расширения и MIME.

Высоты строк, шапки и статус-бара стали функциями (`theme::row_h()`,
`header_h()`, `status_h()`, `scrollbar_w()`), потому что кегль теперь меняется
на лету. Пересчитывать их при смене масштаба не нужно: функция читает текущий
`rem`, а `Theme::update` заставляет окно перерисоваться. Выбранный масштаб
хранится в атомарном `static` — окно одно, а метрики нужны и там, где
`Context` нет (попадание мышью по списку).

Исключения по договорённости — значки: буквы операций в тулбаре (просто цветная
буква без подложки, `font_size()`, полужирная), плашки типов в списке
(`font_size() * 0.85`), стрелка «вверх» (`font_size() * 1.25`), логотип в «О
программе» (`font_size() * 1.7`). Всё считается от того же числа.

**Все элементы управления одного класса.** `theme::CONTROL_SIZE` (`Size::Small`)
задаёт высоту и кегль кнопок, полей ввода, выпадающих списков, числового поля,
галочек и радио. На месте не зовём `xsmall()/medium()` и не пишем свой
`text_size`: для этого есть `ControlSized::control_size()`, `control_input()` и
`dialog_button()`. Иначе в одном диалоге соседние поля оказываются разной
высоты, а «мелкое» поле ещё и печатает другим кеглем.

**Кнопки диалогов — один стиль.** `ui_button()` задаёт единственный вариант и
размер; `dialog_button()`, `close_button()` и погашенные кнопки «✕/Y» идут через
него. Не добавляй `primary()`, `ghost()` или свои `px_*` отдельной кнопке
диалога. Панель меню и тулбар — исключение по договорённости: они остаются
`ghost`, как в 7-Zip FM, но с тем же `CONTROL_SIZE`.

## Темы

«Вид → Тема» переключает `ThemePreference`: **Системная**, **Светлая**,
**Тёмная**, **Блэкаут**, **Графит**, **Серебро**, **Barbie**, **My Little
Pony**, **Гжель**, **Гуро**. По умолчанию стоит **Системная**: при старте берём
оформление платформы (`cx.window_appearance()`), а пока окно открыто — следим за
`cx.observe_window_appearance`. В светлой ОС это штатная светлая тема, в тёмной
— **«Тёмная»** (палитра Carbon). Windows присылает
`WM_SETTINGCHANGE`/`ImmersiveColorSet`, macOS и Linux — своё событие GPUI.
Явно выбранная тема от системного события не зависит.

**«Тёмная»** — почти чёрная с янтарным акцентом; её же получает «Системная»
ночью. **«Блэкаут»** — совсем чёрная (фон `#000000`). **Графит** — тёмная серая,
**Серебро** — светлая серая (чуть темнее белой), **Barbie** — насыщенный
розовый, **Pony** — яркий фиолетовый, **Гжель** — белая с кобальтом, **Гуро** —
тёмный неон (магента и циан).

Светлая и тёмная — штатные режимы кита (`Theme::change`), но «Системная» ночью
берёт нашу «Тёмную», а «Блэкаут» — свою почти чёрную. Остальные палитры лежат в
**`app/themes.json`** — обычном JSON в формате темы gpui-component: имя, `mode`
и цвета по ключам `background`, `button.background`, `list.head.background` и
т. д. При запуске файл ищется рядом с exe (его можно править без пересборки),
потом в текущем каталоге, иначе берётся встроенная копия `include_str!`.

`theme::apply` **после** загрузки темы снова ставит наш кегль (`theme::rem()`):
конфиг темы вправе нести свой размер шрифта. Своих цветов у окна нет —
`Colors::new` каждый кадр читает тему, поэтому список, меню, диалоги и
прогресс перекрашиваются вместе. Выбор живёт на сессию; файл настроек пока не
пишем.

**Про дробный `rem`.** Средний кегль даёт `rem` 15 и текст 13,125 px: строка и
базовая линия попадают на субпиксели, зато кегль компактный. Высоты, которые
считаем сами, округляются до пикселя (`theme::snap`), а текст GPUI рисует с
субпиксельным позиционированием DirectWrite. Если понадобится строго целый
`rem`, достаточно поменять числа в `FontScale::rem` на 14/16/18.

Кегль живёт **в теме**, а не в окне: `Root` из gpui-component на каждой отрисовке
(`RootPlugin::prepare`) делает `window.set_rem_size(cx.theme().font_size)` и
затирает наш `set_rem_size`. Поэтому `theme::init`/`theme::apply` вызывают
`Theme::update` и ставят `font_size = rem()`; гарнитуру оставляем системной —
её выбирает кит.

**Отрисовка текста уже нативная:** Windows-бэкенд GPUI считает глифы через
DirectWrite (`CreateGlyphRunAnalysis`) и растеризует ClearType
(`DWRITE_TEXTURE_CLEARTYPE_3x1`) в атлас, режим — `PlatformDefault` (по
системной настройке ClearType). Отличие от классических Win32-контролов только
в хинтинге: GPUI использует `DWRITE_MEASURING_MODE_NATURAL` и субпиксельное
позиционирование, а Explorer — `GDI_CLASSIC`. Пиксель-в-пиксель как в Explorer
потребует форка `gpui-pre-windows` (~12 тыс. строк) через `[patch.crates-io]`:
`GDI_CLASSIC`, `GDI`-measuring, целые позиции глифов.

## Автодополнение адреса

Ctrl+L (или клик по адресу) открывает поле. Пока печатаете, подсказка — бледный
хвост прямо за курсором, как в терминале: `C:\Wi` → `ndows\`. Tab дополняет
(каталогу добавляет `\`), Enter принимает хвост и сразу переходит, Escape
сначала убирает хвост, затем закрывает поле. Если совпадений несколько, хвост —
их общий префикс; когда общего нет, Tab берёт первый вариант, который
действительно дополняет.
Выпадающего списка нет: он перекрывал файлы и принимал клики мимо цели.

`fsutil::completion_ghost` считает хвост по именам из `list_address_suggestions`.
`ui_chrome` рисует невидимую копию набранного текста и хвост за ней — так
позиция не зависит от измерения глифов. Хвост виден только когда курсор в конце
строки, нет выделения и поле не прокручено.

## Верхнее меню

Меню — управляемый `PopupMenu` (не `Button::dropdown_menu`): при открытом меню
наведение на соседний заголовок сразу переключает попап, как в Windows. Клик
по заголовку открывает/закрывает, Escape и клик вне закрывают, фокус после
закрытия возвращается списку. `--menu-view` открывает «Вид» на старте.

## Две панели

F9 включает и выключает вторую панель (как в 7-Zip FM), Tab переключает активную.
Панели стоят рядом, у каждой свой адрес, вид, сортировка и выделение; меню,
тулбар, прогресс и статус-бар — общие. Активная панель отмечена цветной полоской
и рамкой адресной строки: иначе не видно, куда уйдут Enter, Del и F5.

- При первом включении вторая панель открывается в той же папке; если активен
  архив — в папке, где он лежит (оттуда и распаковывают).
- F5/F6 и диалог извлечения по умолчанию предлагают вторую панель, если она
  открыта на каталоге. Это и есть смысл режима: одна панель — источник, другая —
  приёмник.
- Alt+Up открывает текущую папку в другой панели. Клик по панели делает её
  активной; Tab делает то же с клавиатуры.
- Файлы и папки можно тащить из одной панели в другую: **перетаскивание копирует**,
  Shift — перемещает. Отпустили на строку папки — копируем **в неё**, отпустили
  на файл или пустое место панели — в текущий каталог этой панели. Совпадающие
  имена не перезаписываются (`Skip`), внутрь архива тащить нельзя — сначала
  извлеките.
- Вокруг панелей рамка протяжки своя у каждой; клик по второй панели не сбрасывает
  выделение в первой.
- Выключение (F9) оставляет активной левую панель; правая запоминает своё место
  до следующего включения.

## На будущее: тема Windows XP

Идея на потом, не текущая задача. Цель — переключаемая тема в духе Windows XP
(Luna): серый фон панелей, синие заголовки и градиентные кнопки, утопленные
поля, классические меню и тулбар. Не копировать пиксели Explorer, а повторить
узнаваемый вид, не ломая нынешнюю сетку и кегль.

Сейчас в «Вид → Тема» уже есть `System/Light/Dark`: XP станет ещё одним
значением `ThemePreference`, а не вторым механизмом переключения.

Как делать, чтобы не разошлось с текущими правилами:

- Добавить `ThemePreference::Xp` и палитру-токены в `theme.rs`; виджеты
  должны брать цвета из `Colors`, а не из своих констант.
- Метрики (высоты строк, шапки, кнопок) оставить общими: тема меняет цвета,
  рамки, градиенты и радиусы, но не ломает виртуализацию списка.
- Кегль остаётся один (`theme::FONT_SIZE`); XP-вид не повод вводить второй.
- Настройку темы пока не сохраняем: режим живёт сессию; файл настроек —
  отдельная задача.
- Проверять `scripts/shot.ps1` на тех же сценариях: список, две панели, меню,
  диалоги, прогресс — сначала в светлой, потом в тёмной теме.

Значки от темы не зависят: это системные иконки ОС (см. «Значки»). XP-тема их
не подменяет — свой набор иконок был бы отдельным ресурсом, а не палитрой.

## Диалоги

Диалоги создания, извлечения, проверки, переноса, «папка/файл» и «О программе» —
**слои внутри окна**: каркас свой, поля и кнопки штатные (`Input`, `Button`,
`Checkbox`, `Radio`, `NumberInput`, `GroupBox`). Так состояние диалога живёт в
одной структуре окна и не требует отдельной сущности.

Подтверждение удаления — **диалог кита**: `window.open_alert_dialog(...)`.

Спайк (0.9.1) показал, что `WindowState` находится: он регистрируется плагином
`gpui_base::Root`, а `gpui_kit::open_window` монтирует именно его. Старая ошибка
«component window state is missing» была следствием рассинхрона версий
`gpui-base` у `gpui-kit` и `gpui-component`, а не архитектуры. Проверено делом:
Del → диалог → Enter → файл удалён, окно живо.

Почему мигрирован только он: builder `open_dialog` вызывается повторно, поэтому
все поля ввода должны жить в `Entity`, а не в `Window`; для диалогов с полями это
отдельная работа. У подтверждения полей нет — самый дешёвый случай.

Правило: ввод принадлежит `InputState`; при открытом диалоге кита корень окна
клавиши не обрабатывает (`window.has_active_dialog(cx)`) и список под ним не
строится. Ошибки («имя занято», «пароль не совпал») показываем **в диалоге**
красной строкой: в статус-баре их не видно.

## Автоматизация UI

```powershell
.\scripts\shot.ps1 -Out preview.png
.\scripts\shot.ps1 -Out x.png -Arguments "$PWD\target\smoke\sample.7z"
.\scripts\shot.ps1 -Build -Out x.png -Arguments "$PWD\target\smoke\demo","--select=3" -Keys "{ENTER}"
.\scripts\shot.ps1 -Out x.png -ClickX 253 -ClickY 77
```

`-Build` убивает запущенный экземпляр и собирает (иначе `cargo build` падает с
«Access is denied»: живое окно держит exe). `-Keys` шлёт настоящее нажатие через
`SendKeys`, `-Drag "x1,y1,x2,y2"` — протяжку мышью (`-DragHold` не отпускает
кнопку, чтобы снять кадр посреди жеста), `-Hover "x,y"` — наведение без клика
(проверка hover-переключения меню).

| Флаг | Что делает |
|---|---|
| `--theme=dark` | стартовать в теме: `system`, `light`, `dark`/`carbon` («Тёмная»), `blackout`, `graphite`, `silver`, `barbie`, `pony`, `gzhel`, `guro` |
| `--font=large` | масштаб текста: `small`, `medium`, `large` |
| `--address=C:\Wi` | открыть поле адреса с введённым текстом (проверка автодополнения) |
| `--two-panel` | показать две панели сразу при запуске |
| `--right=<путь>` | открыть вторую панель на заданном пути (включает две панели) |
| `--extract` | открыть диалог извлечения и сразу подтвердить |
| `--extract-dialog` | только открыть диалог извлечения |
| `--add` | открыть диалог создания, выделив всё |
| `--create-now` | открыть и сразу создать |
| `--menu-view` | раскрыть меню «Вид» |
| `--select=0,2` | предустановить выделение по индексам |
| `--test-now` | запустить проверку архива (`7z t`) сразу |
| `--title-bench` | замерить стоимость `SetWindowText` |

Флаги действуют только при `ARCHIVER_TEST_FLAGS=1` — в продуктовом бинаре
случайный `--add` ничего не запускает. `scripts/shot.ps1` выставляет переменную
сам, разбор — в `launch.rs` (там же тесты).
